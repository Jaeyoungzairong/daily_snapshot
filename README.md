# Daily Snapshot

매일 아침 확인하는 날씨 · 환율 · 오늘 할일 · 공유 파일 · 자주 가는 사이트를 한 화면에 모아
보여주는 대시보드입니다. 웹(정적 사이트, Firebase Hosting 배포)과 안드로이드 앱(사내 배포용
APK) 두 플랫폼을 지원하며, 로그인·데이터 동기화·파일 저장은 Firebase(Auth/Firestore/Storage)를
공통으로 사용합니다. 안드로이드는 할일·메모·공유 파일함만 지원하고(날씨/환율/바로가기는 웹
전용), 로그인 방식도 플랫폼별로 다릅니다 — 아래 "로그인 / 계정" 참고.

## 주요 기능

### 날씨
- 기상청 단기예보 API(`VilageFcstInfoService_2.0`)의 초단기실황(`getUltraSrtNcst`) + 단기예보(`getVilageFcst`)를 조합해
  현재 기온/하늘상태와 시간별 예보를 표시
- 강수확률(POP), 강수량(PCP/RN1) 표시
- 도시 검색 시 번들된 기상청 격자 지역 목록(`assets/kma_regions.json`)에서 좌표를 찾아 기상청 격자(nx, ny)로 변환
- 검색창의 "내 위치로 찾기" 버튼으로 브라우저 위치를 조회해 가장 가까운 기상청 지점을 자동 선택
  (한반도에서 100km 넘게 벗어난 좌표는 지원하지 않음)
- 마지막으로 선택한 도시를 저장해 다음 방문 시 자동으로 불러옴
- 지금 화면에 없는 도시의 예보 캐시는 정리함(탭을 오래 켜두고 도시를 여러 번 바꿔도 메모리가
  쌓이지 않음) — 대신 이전에 봤던 도시로 돌아가면 다시 조회
- 30분마다, 그리고 탭/앱으로 돌아왔을 때(마지막 조회가 30분 넘었을 때만) 자동으로 다시 조회함 —
  아침에 열어 둔 탭이 종일 그때 기온과 시간별 예보("지금" 표시)를 보여주던 문제. 기상청 실황은
  매시 40분경, 예보는 3시간마다 바뀌어서 더 자주 부를 이유가 없음. 웹은 다른 창을 눌렀다 돌아오는
  것만으로도 "복귀"라 복귀 기준도 같은 30분으로 맞춤. 다시 받는 동안에도
  이전 값을 그대로 보여주고, 갱신에 실패해도 에러 화면으로 바꾸지 않고 마지막 값과 "갱신 실패"를
  표시함. 카드 우측 상단에 조회 시각("HH:mm 기준")을 표시

### 환율
- [open.er-api.com](https://open.er-api.com)에서 실시간 환율 시세 조회
- [frankfurter.dev](https://api.frankfurter.dev)에서 기간별 환율 히스토리 조회 후 차트로 표시(`fl_chart`)
- 1시간마다, 그리고 탭/앱으로 돌아왔을 때(마지막 갱신이 1시간 넘었거나 직전 갱신이 실패했을 때)
  자동 갱신 — 최신 환율은 하루 한 번, 그래프(ECB)는 영업일에만 바뀌어 더 자주 부를 이유가 없음.
  갱신 중에도 이전 값을 그대로 보여주고, 실패하면 에러 화면 대신 마지막 값과 실패 안내를
  표시함(처음 조회가 실패했을 때만 에러 화면). 그래프는 지금 보는 조합만이 아니라 전체 캐시를
  비워서, 나중에 다른 통화/기간을 골라도 옛 캐시 값이 나오지 않음
- 통화 선택은 목록에서 고르기만 가능(텍스트 입력/키보드 비활성화)
- 간단 환산 입력창은 숫자/소수점만 남도록 처리하되, 한글 IME 조합 중에는 손대지 않아
  조합 중 기존 입력값이 사라지는 문제를 방지

### 로그인 / 계정
- 화면 우측 상단 계정 아이콘에서 로그인·로그아웃을 한 곳에서 처리(특정 카드에 종속되지 않고
  전역에서 접근 가능)
- **웹**: Firebase 이메일 링크(비밀번호 없는) 로그인. 관리자가 Firestore에 등록·활성화한
  이메일만 로그인할 수 있고, 미승인 이메일은 로그인 링크 발송 자체를 하지 않음(발송 한도 절약,
  "링크가 안 왔나?" 하는 혼란 방지). 메일 링크를 클릭해 앱으로 돌아오면 계정 다이얼로그가
  자동으로 열리고, 그 안에서 "로그인 계속하기"를 직접 눌러야 로그인이 완료됨 — 메일 보안
  스캐너가 링크를 미리 열어봐도 1회용 로그인 코드가 그 자리에서 소모되지 않도록 하기 위함.
  승인 여부는 링크를 소모하기 전에 먼저 확인하고, 이 브라우저에 저장해 둔 요청 이메일은 로그인에
  실제로 성공했을 때만 지움 — 그래서 네트워크 오류나 승인 대기 중이면 같은 링크로 "로그인
  계속하기"를 다시 누를 수 있음(만료·이미 사용된 링크처럼 재시도해도 소용없는 경우에만 새 링크 요청 안내)
- **안드로이드**: Google 계정으로 로그인(Google Sign-In). 사내 메일 앱이 딥링크를 가로채
  이메일 링크 방식을 쓸 수 없어 채택함. 로그인한 Google 계정이 승인 명단에 없으면 즉시
  거부되고, 그 시도로 서버에 남은 미승인 계정도 자동으로 삭제됨(방치된 빈 계정이 나중에
  같은 Google 계정의 정상 연동을 막는 문제 방지)
- **계정 연동(웹 전용 설정)**: 관리자가 `admin_allowed_emails/{email}` 문서에
  `androidAccessEnabled: true`를 켜준 사용자는, 계정 다이얼로그에서 지금 로그인된 회사메일
  계정에 Google 계정을 연동할 수 있음("Google 계정 연동하기"). 연동해두면 안드로이드에서 그
  Google 계정으로 로그인했을 때 완전히 새 계정이 아니라 같은 uid로 들어와, 웹에서 쓰던
  할일/메모/공유 파일함 데이터를 안드로이드에서도 그대로 이어서 볼 수 있음. 연동 해제 시에는
  이 계정으로 로그인된 모든 기기(안드로이드 세션 포함)가 함께 로그아웃됨. `androidAccessEnabled`가
  꺼진 사용자에게는 이 버튼 자체가 보이지 않아 임의로 연동을 시도할 수 없음(단, 이미 연동된
  계정은 필드가 꺼져 있어도 해제 버튼은 계속 보여서 스스로 해제할 방법이 없어지지 않게 함)
- 계정 다이얼로그의 "다른 모든 기기에서 로그아웃"으로 이 계정으로 로그인된 모든 세션(이
  기기 포함)을 무효화 가능. Firestore 보안 규칙이 거부할 때까지 기다리지 않고, 승인 명단
  문서를 실시간 구독해 다른 기기/탭에서도 바로 로그아웃 처리됨(플랫폼·로그인 방식과 무관하게
  동일하게 동작)
- "다른 모든 기기에서 로그아웃"과 Google 연동 해제는 서버에 연결되는지 먼저 확인하고, 오프라인이면
  시작하지 않고 안내함(예전엔 스피너만 무기한 돌고, 그 사이 탭을 닫으면 실제로는 로그아웃되지 않았음)
- 로그인 중 승인 확인이 끝날 때까지 계정 다이얼로그를 닫지 않음 — 미승인 Google 계정으로 로그인하면
  "관리자 승인이 필요" 안내가 다이얼로그에 그대로 보임
- 로그아웃(모든 기기 로그아웃, Google 연동 해제 포함) 직전에 저장 대기 중인 메모를 먼저 저장하고,
  저장하지 못한 내용이 남으면(오프라인 등) "그래도 로그아웃"할지 한 번 더 확인함
- 로그인해야 이용 가능한 기능: 오늘 할일/메모, 공유 파일함

### 오늘 할일 / 메모
- 할 일과 메모는 별도의 카드(각자 고유 강조색)로 분리되어 있음
- 체크리스트(완료 항목은 취소선만 표시하고 목록 순서는 그대로 유지 — 완료했다고 아래로 밀리지
  않음), 항목 삭제와 완료 항목 일괄 삭제 시 확인 다이얼로그로 실수 방지. 현재 개수(n/30)를
  상시 표시하고, 15개를 넘으면 이전/다음 버튼으로 페이지를 넘겨 확인
- 메모는 제목을 붙여 여러 개를 만들어 관리(칩 형태 선택기), 좌우 버튼으로 순서 변경 가능, 삭제 시 확인 다이얼로그
- 로그인 후 이용 가능(플랫폼별 로그인 방법은 위 "로그인 / 계정" 참고)
- 데이터는 Firestore에 저장되어 기기 간 동기화됨(같은 계정으로 로그인하면 어디서든 동일한 목록을 봄).
  트랜잭션으로 갱신해 여러 기기에서 거의 동시에 수정해도 나중 쓰기가 앞선 변경을 덮어쓰지 않음
  (낙관적 로컬 갱신 + 실시간 스트림 반영)
- 저장에 실패하면(오프라인, 권한 거부 등) 화면을 마지막으로 받은 서버 상태로 되돌리고 스낵바로
  알림 — 여러 변경이 겹쳐 실패해도 저장 안 된 변경이 화면에 남지 않음. 할 일 추가가 실패하면
  입력한 글은 지우지 않아 바로 다시 시도 가능
- 메모 제목/내용은 입력을 멈추면 자동 저장(0.5초 디바운스). 자동 저장이 실패하면 입력한 내용은
  화면에 그대로 두고, 저장될 때까지 메모 카드 위에 "저장되지 않은 메모 변경 사항이 있습니다" 배너와
  "다시 저장" 버튼을 계속 표시함(메모 전환·로그아웃 때도 자동으로 다시 시도)
- Firestore 문서의 항목 일부가 손상돼도(콘솔 수동 편집 등) 읽을 수 없는 항목만 건너뛰고 나머지는
  정상 표시하며, 손상된 항목은 저장할 때 지우지 않고 그대로 보존
- 안드로이드에서 입력창 바깥을 누르거나 화면을 스크롤하면 키보드가 내려감(Flutter 모바일 기본
  동작은 바깥을 눌러도 포커스를 유지함)
- 항목별 생성/완료 시각을 함께 저장해 추후 날짜별 기록 조회 기능 확장을 고려한 데이터 구조
- 도시 선택/테마처럼 기기 하나에만 있으면 되는 값은 그대로 로컬(`shared_preferences`)에 저장 — 로그인이
  필요한 건 할일/메모뿐

### 바로가기
- 자주 쓰는 외부 사이트(그룹웨어, 사내 NAS, 지도, 메일, 검색 등)를 아이콘 목록으로 두고 클릭 시 새 탭으로 이동

### 공유 파일함
- Firebase Storage + Firestore로 파일을 올리고 받는 기능. 계정별 저장소가 아니라 승인된 모든
  사용자가 함께 쓰는 공유 풀(파일 하나당 최대 150MB, 전체 최대 30개)
- 로그인 후 이용 가능(플랫폼별 로그인 방법은 위 "로그인 / 계정" 참고). 업로드·다운로드는 승인된
  사용자 누구나 가능하고(미리보기는 웹 전용, 아래 참고), 삭제는 관리자(승인 명단의 `isAdmin: true`)는
  전체 파일을, 일반 사용자는 본인이 올린 파일만 가능
- 확장자별로 미리보기 가능 여부를 판단해 pdf/이미지/텍스트/mp4/mp3는 "미리보기"(새 탭에서 열기)와
  "다운로드"(실제 저장)를 아이콘으로 구분 제공. 다운로드는 Storage 버킷 CORS 설정 + 브라우저에서
  바이트를 직접 받아 Blob으로 저장하는 방식으로, 미리보기 가능한 형식도 정확히 파일로 저장됨.
  미리보기는 "새 탭에서 열기"에 기대는 기능이라 웹 전용이고, 안드로이드는 다운로드만 지원
  (`file_saver`로 기기에 저장하고, 저장에 성공/실패하면 스낵바로 알림)
- 다운로드 전에 파일명과 크기를 보여주는 확인 다이얼로그를 띄움(잘못 눌러 큰 파일을 받는 것 방지 —
  특히 안드로이드 모바일 데이터)
- 업로드·다운로드 모두 진행률을 표시(대용량 파일에서도 버튼이 응답 없어 보이지 않도록). 다운로드는
  30초 동안 데이터가 전혀 오지 않으면(정체) 중단하고 알림 — 전체 시간 제한이 아니라서 데이터가
  계속 들어오는 대용량 파일은 끊기지 않음
- 파일 메타데이터 문서 일부가 손상돼도(콘솔 수동 편집 등) 읽을 수 없는 문서만 목록에서 건너뛰고
  나머지는 정상 표시(공유 컬렉션이라 예전엔 문서 하나 때문에 모든 사용자의 파일함이 에러 화면이 됐음).
  건너뛴 문서는 지우지 않으므로 콘솔에서 고치면 다시 나타남
- 업로드는 성공했는데 목록(Firestore) 등록만 실패하면, 방금 올린 Storage 파일을 지우려고 시도함
  (목록에 안 보이는 파일이 용량만 차지하지 않도록 — 한계는 아래 "알려진 미해결 이슈" 참고)
- 여러 파일을 한 번에 선택해 업로드 가능, 일부만 실패해도 나머지는 계속 진행. 이미 같은 이름의
  파일이 있으면 업로드 전에 확인(취소/그래도 업로드 중 선택)
- 최신 업로드 순 정렬, 현재 개수(n/30)를 상시 표시. 10개를 넘으면 이전/다음 버튼으로 페이지를
  넘겨 확인하며, 업로드에 성공하면 방금 올린 파일을 바로 볼 수 있도록 1페이지로 돌아감

### 화면 테마 / 레이아웃
- 앱바 아이콘으로 다크/라이트 테마 전환, 마지막으로 선택한 테마를 저장해 다음 방문 시 그대로 적용.
  저장소를 읽거나 쓰지 못해도(플러그인 오류 등) 기본값(다크 테마, 서울)으로 정상 시작함
- 전체 글꼴을 Pretendard(Regular/SemiBold)로 번들링해 플랫폼(기기별 시스템 한글 폰트)에
  관계없이 항상 동일하게 보이도록 통일
- 폭 900px 이상이면 카드를 2열로 배치(카드 폭은 화면에 맞춰 최대 560px), 그보다 좁으면 1열
- 안드로이드는 화면이 하단 네비게이션 바 뒤까지 그려지므로(edge-to-edge), 맨 아래까지 스크롤하면
  마지막 카드와 버전 표시가 바에 가리지 않도록 바 높이만큼 여백을 둠
- 앱 버전은 대시보드 맨 아래 오른쪽에 표시

### 외부 API 오류 처리 (날씨 / 환율)
- 서버가 15초 안에 응답하지 않으면 요청 자체를 취소하고 "서버 응답이 없습니다" 안내
- 응답이 예상과 다른 형식이면(필드 누락, 잘못된 JSON 등) Dart 내부 오류 문구 대신 한국어 안내
- 이런 오류는 자동으로 재시도하지 않고 바로 에러 화면과 "다시 시도" 버튼을 보여줌(Riverpod 기본
  자동 재시도를 그대로 두면 최대 10번 재시도하는 동안 로딩 스피너만 수십 초~수 분 보였음)

## 기술 스택
- Flutter Web + Android (두 플랫폼 공통 코드베이스, 날씨/환율/바로가기는 웹 전용)
- 상태 관리: `flutter_riverpod` 3 (`AsyncNotifier`/`StreamNotifier`/`Notifier` 기반). 외부 API
  provider는 `ApiException`을 자동 재시도하지 않도록 `retry` 정책을 따로 지정(`api_retry.dart`)
- 인증/데이터베이스: `firebase_auth`(웹은 이메일 링크, 안드로이드는 `google_sign_in` 기반 Google
  로그인) + `cloud_firestore`(할일/메모/공유 파일함 메타데이터 동기화). 보안 규칙에서 로그인 승인
  명단(`admin_allowed_emails`)을 함께 검증 — 단건 조회(`get`)는 누구나 가능하게 열어 로그인 전에도
  승인 여부를 미리 확인할 수 있게 하고, 목록 조회(`list`)는 막아 전체 승인자 목록이 노출되지 않게
  함. 같은 문서의 `isAdmin` 필드로 파일 삭제 등 관리자 전용 동작을, `androidAccessEnabled` 필드로
  Google 계정 연동(안드로이드 접근) 허용 여부를 구분
- 파일 저장: `firebase_storage`(공유 파일함 실 파일 저장) + `file_picker`(파일 선택) + `file_saver`
  (다운로드한 바이트를 기기에 저장 — 웹은 자체 Blob 다운로드를 쓰고, 안드로이드만 이 패키지를 씀)
- 로컬 저장소: `shared_preferences` (공통 `KeyValueStore` 추상화로 감싸 테스트에서 인메모리로 대체)
- 앱 버전 표시: `package_info_plus` — 웹은 `flutter build web`이 생성하는 `version.json`, 안드로이드는
  설치된 앱의 네이티브 버전 정보를 읽어와 별도 주입 없이 `pubspec.yaml`의 `version`을 표시(빌드번호
  `+N`은 제외)
- 차트: `fl_chart`
- HTTP: `http` (환율/날씨 API 호출 + 공유 파일함 다운로드 스트리밍). 타임아웃은 `Future.timeout`이
  아니라 `AbortableRequest`로 실제 요청을 취소하는 방식
- 글꼴: [Pretendard](https://github.com/orioncactus/pretendard) (Regular/SemiBold, `assets/fonts/`에 번들링, OFL 라이선스)

## 로컬 개발

### 1. 의존성 설치
```bash
flutter pub get
```

### 2. API 키 설정
기상청 API를 쓰려면 서비스 키가 필요합니다. `lib/core/config/secrets.example.json`을 참고해
같은 위치에 `secrets.json`(gitignore됨, 커밋되지 않음)을 만들고 실제 키를 넣습니다.

```json
{
  "KMA_SERVICE_KEY": "YOUR_KMA_SERVICE_KEY_HERE"
}
```

### 3. 실행
```bash
flutter run -d chrome --dart-define-from-file=lib/core/config/secrets.json
```

> `flutter run -d chrome`은 매 실행마다 임시 브라우저 프로필을 새로 띄우므로, 세션이 끝나면
> `localStorage`(도시/테마 선택값, 로그인 세션)가 초기화됩니다. 데이터가 계속 유지되는 상태로
> 확인하려면 아래처럼 빌드 후 고정 포트로 정적 서빙하는 방법을 씁니다.

> 할일/메모는 Firebase 이메일 링크 로그인이 필요하고, 그중에서도 Firestore의
> `admin_allowed_emails` 컬렉션에 등록·활성화(`isActive: true`)된 이메일만 로그인할 수
> 있습니다. 로컬에서 이 기능까지 테스트하려면 별도 Firebase 프로젝트를 만들고
> `lib/firebase_options.dart`를 그 프로젝트 설정으로 교체한 뒤, `firestore.rules`를 배포하고
> 본인 이메일을 승인 명단에 추가해야 합니다(규칙 배포 방법은 아래 "배포 > 보안 규칙" 참고).

> 공유 파일함까지 테스트하려면 위 설정에 더해 `storage.rules`도 배포하고, Storage 버킷 설정에서
> CORS(허용 origin에 로컬 서빙 주소 포함, `GET`, 응답 헤더 `Content-Type`/`Content-Length`)를
> 켜야 다운로드 진행률·강제 저장이 동작합니다. 파일 삭제까지 테스트하려면 승인 명단 문서에
> `isAdmin: true`도 추가합니다.

```bash
flutter build web --dart-define-from-file=lib/core/config/secrets.json
dhttpd --path build/web --port 8766
```
그 후 브라우저에서 `http://localhost:8766`으로 접속하면 됩니다(같은 고정 주소를 계속 쓰므로
브라우저의 일반 프로필에 데이터가 유지됩니다). 코드를 수정하면 `flutter build web`을 다시
실행해야 반영됩니다.

> 화면 우측 하단의 버전 표시는 `pubspec.yaml`의 `version`을 읽어오므로, 로컬 빌드에서도
> 실제 값(예: `v26.9.18`, 빌드번호 `+1`은 표시하지 않음)이 보입니다.

### 안드로이드 빌드
```bash
flutter build apk
```
`--dart-define-from-file`은 안드로이드에는 필요 없습니다. 이 값이 주입하는 `KMA_SERVICE_KEY`는
날씨 기능([kma_weather_repository.dart](lib/features/weather/data/kma_weather_repository.dart))만
쓰는데, 날씨 카드 자체가 `if (kIsWeb)`로 안드로이드에서는 아예 빌드되지 않기 때문입니다
([dashboard_page.dart](lib/features/dashboard/presentation/dashboard_page.dart) 참고). Firebase
설정도 dart-define이 아니라 `google-services.json`에서 오므로 로그인·동기화와도 무관합니다.
(안드로이드에 날씨 기능이 추가되면 이 문단도 같이 갱신해야 합니다.)

안드로이드는 로그인 방식이 웹과 다릅니다(이메일 링크 대신 Google Sign-In, 위 "로그인 / 계정"
참고). 로컬에서 로그인까지 테스트하려면:
- 사용할 Firebase 프로젝트에 안드로이드 앱을 추가하고, 디버그/릴리스 각각의 서명 키
  SHA-1을 등록한 뒤 새로 받은 `google-services.json`을 `android/app/`에 둡니다
  (`google_sign_in`이 이 파일의 `client_type: 3` 웹 클라이언트 항목을 자동으로 읽어 쓰므로
  별도 클라이언트 ID 설정은 필요 없습니다).
- Firebase 콘솔의 Authentication에서 Google 로그인 제공자를 켭니다.
- 로그인하려는 Google 계정의 이메일을 승인 명단(`admin_allowed_emails`, `isActive: true`)에
  등록합니다. 회사메일 계정과 같은 데이터를 이어서 보려면, 웹에서 먼저 그 회사메일 계정으로
  로그인한 뒤 계정 다이얼로그에서 이 Google 계정을 연동(`androidAccessEnabled: true` 필요)해야
  합니다.

> 앱 아이콘은 `flutter_launcher_icons`(dev 의존성)로 생성합니다. 웹 아이콘(`web/icons/Icon-512.png`,
> `Icon-maskable-512.png`)을 원본으로 써서 로고가 한 벌만 유지되며, 로고를 바꾸면 웹 아이콘 두 장을
> 교체한 뒤 `dart run flutter_launcher_icons`로 `android/app/src/main/res`의 아이콘을 다시 만듭니다
> (설정은 `pubspec.yaml` 맨 아래, Android 8+ 적응형 아이콘 포함).

> `file_saver`가 끌어오는 `jni`/`jni_flutter` 패키지가 CMake와 Android SDK Platform 35를 요구해서,
> 이 구성요소가 없는 PC에서는 첫 release 빌드 때 Gradle이 자동으로 설치합니다(한 번만, 빌드가
> 평소보다 오래 걸림). 빌드 로그의 Kotlin Gradle Plugin 경고는 아래 "알려진 미해결 이슈" 참고.

## 배포
`main` 브랜치에 push되면 `.github/workflows/deploy-firebase.yml`이 Firebase Hosting
(`daily-snapshot-3ff12.web.app`)에 자동 배포합니다. 이전에 쓰던
`.github/workflows/deploy.yml`(GitHub Pages)은 Firebase Hosting 안정성을 지켜보는 동안
수동 실행(`workflow_dispatch`)으로만 남겨뒀고, 문제가 생기면 트리거를 다시 되돌려 즉시
롤백할 수 있습니다. 두 워크플로 모두 빌드 단계는 `.github/actions/build-web` 컴포짓
액션을 공유합니다. `KMA_SERVICE_KEY`는 저장소 Settings > Secrets에 등록된 값을 빌드 시
`--dart-define`으로 주입합니다.

Firebase Hosting 설정(`firebase.json`)은 SPA 라우팅을 위한 rewrite와, 모든 파일에
`Cache-Control: no-cache`(매번 서버에 확인하되 바뀌지 않았으면 ETag로 304 — 본문은 다시 받지 않음)를
둡니다. Flutter 웹 산출물(`main.dart.js`, `canvaskit/`, 이미지 등)은 파일명에 해시가 붙지 않아서,
장기/immutable 캐시를 걸면 배포 후에도 브라우저가 옛 코드를 계속 실행합니다(실제로 예전 설정이
그랬음). `web/index.html`과 `web/flutter_bootstrap.js`의 `?v=2` 쿼리는 그 옛 캐시를 이미 받아둔
브라우저를 한 번 빠져나오게 하기 위한 것이라 배포마다 올릴 필요는 없습니다. 단, 이미 immutable로
캐시된 이미지와 `canvaskit/`은 URL이 그대로라 기존 사용자 브라우저에 최대 1년간 남을 수 있습니다
(Flutter 업그레이드로 canvaskit이 바뀌면 그런 브라우저는 강력 새로고침이 필요할 수 있음).

### 보안 규칙 (Firestore / Storage)
CI로 배포하지 않고, Firebase 콘솔의 규칙 편집기(Firestore Database → 규칙, Storage → 규칙)에
`firestore.rules`/`storage.rules` **파일 전체 내용을 붙여넣어 게시**합니다. 편집기는 붙여넣은 텍스트를
그대로 적용하므로 일부만 붙이면 나머지 규칙이 사라집니다. 이 방식이라 `firebase.json`에 `firestore`
항목이 없는 게 정상입니다(CLI `firebase deploy --only firestore:rules`로 바꾸려면 그때
`"firestore": {"rules": "firestore.rules"}`를 추가). 저장소의 규칙 파일을 고친 뒤 콘솔에 붙여넣기
전까지는 운영 규칙에 반영되지 않습니다.

### 안드로이드 APK
자동 배포 없이 수동으로 배포합니다. 로컬에서 `flutter build apk`로 서명된 release APK를 만든 뒤,
Firebase 콘솔 → App Distribution → 출시 탭에 올리고 테스터 그룹을 골라 배포합니다(테스터는 초대
메일을 수락해야 설치 가능). 서명 키(`android/key.properties`, `*.jks`)와 `google-services.json`은
로컬에만 두고 GitHub Secrets에 올리지 않기로 해서, GitHub Actions(클라우드 러너)로는 서명된 APK를
만들 수 없습니다. 같은 날 다시 배포할 때는 `pubspec.yaml`의 빌드번호(`+N`)를 올려야 기존 설치 앱에
업데이트로 설치됩니다(안드로이드 `versionCode`).

### 버전 관리
`pubspec.yaml`의 `version`은 `dev` 브랜치를 `main`에 병합할 때마다 그날 날짜 기준
`YY.M.D+빌드번호`(예: `26.8.31+1`) 형식으로 갱신합니다. 같은 날 다시 배포하면 빌드번호만
올립니다. 이 값은 `package_info_plus`가 웹은 `flutter build web`이 자동 생성하는
`build/web/version.json`을, 안드로이드는 설치된 앱의 네이티브 버전 정보를 읽어와 화면
우측 하단에 표시합니다 — 별도 주입 없이 `pubspec.yaml`의 `version`이 반영되며, 빌드번호는
같은 날 재배포를 구분하는 내부 값이라 화면에는 `YY.M.D` 부분만 보여줍니다. 병합 후
GitHub의 Releases 기능으로 같은 버전(`v26.8.31`)의 태그를 남기며, 별도 CHANGELOG 파일은
두지 않고 커밋 메시지/릴리스 노트로 대신합니다.

- 공유 파일함(업로드 상한, 중복 파일명 처리, 다운로드 진행률 등)에 대한 자동화 테스트 추가 — 현재는
  다운로드 확인 다이얼로그 테스트만 있음
- GitHub Pages 배포 경로 완전 정리 — Firebase Hosting 안정성이 충분히 확인되면 제거
- 관리자(나)만 접근 가능한 개인 파일함 — 공유 파일함과 별도 풀로 검토 중
- 안드로이드 앱을 실제 동료에게 배포(승인 명단에 `androidAccessEnabled: true` 부여) — 아직
  본인 계정으로만 실기기 검증 중
- 안드로이드 스토어 배포 여부 정리 — 현재는 App Distribution으로 사내 공유하는 APK 수준(앱 아이콘은
  2026-09-28에 로고로 교체 완료)

## 알려진 미해결 이슈 (검토했지만 아직 미적용)
- **공유 파일함 개수 상한(30개) 클라이언트에서만 확인함.** 두 탭/기기가 동시에 29번째
  업로드를 시도하면 둘 다 통과해 상한을 넘길 수 있음(용량 상한은 서버 규칙에도 있어 그쪽은
  안전). 서버 규칙에서 개수까지 확인하려면 별도 설계 필요.
- **할 일(30개)/메모(15개) 개수 상한도 같은 이유로 클라이언트에서만 확인함.** 다만 uid별
  개인 데이터라 동시 접속 자체가 드물고, 상한을 살짝 넘겨도 문서 크기가 Firestore 1MiB
  제한에 전혀 근접하지 않아(수십 개 더 늘어도 수 KB 수준) 실질적 피해가 없어 우선순위를
  낮게 둠(2026-09-18 검토).
- **파일 미리보기/다운로드 URL이 영구 접근 가능한 토큰 방식.** 한 번 발급된 URL은 이후
  승인이 해제되거나(`isActive:false`) 강제 로그아웃되어도 계속 유효함(Firebase Storage
  `getDownloadURL()`의 표준 동작). 접근을 진짜로 회수하려면 짧은 만료 시간의 서명 URL 등
  다른 방식이 필요.
- **날씨 카드에서 "내 위치로 찾기" 조회 중 수동으로 다른 도시를 검색해 선택해도, 나중에
  위치 조회 결과가 도착하면 그걸로 덮어씀.** 검토 결과 어느 쪽을 우선해야 할지 단정하기
  어려운 설계 선택의 문제로 보여 일단 보류함(2026-09-17 검토).
- **저장 실패한 메모 편집은 제목/내용 각각 한 건만 기억함.** 저장이 실패한 채로 다른 메모로 옮겨
  그 메모를 편집하면, 앞 메모의 저장 안 된 편집이 새 편집으로 덮여 사라짐(배너는 계속 뜨지만 사라진
  쪽은 알려주지 않음). 원래 디바운스 구조(필드별 대기 슬롯 하나)의 한계(2026-09-28 검토).
- **두 기기에서 같은 메모의 같은 필드(제목 또는 내용)를 동시에 입력하면 나중에 저장한 쪽이 이김.**
  한쪽만 편집 중이면 다른 기기의 변경은 편집창에 자동 반영되지만(입력하지 않는 필드는 따라가고,
  입력 중인 필드는 보호), 양쪽이 동시에 입력하면 먼저 저장된 쪽이 조용히 덮임. 막으려면 저장 시
  `updatedAt` 비교나 "다른 기기에서 수정됨" 안내가 필요(2026-09-29 검토).
- **웹 탭을 닫을 때 저장 안 된 메모 경고가 없음.** 배너로만 알림 — 브라우저 "나가시겠습니까?"
  경고는 웹 전용 코드가 필요해 보류.
- **업로드 후 목록 등록 실패 시 Storage 정리는 관리자만 성공함.** `storage.rules`의 삭제 규칙이
  (관리자가 아니면) Firestore 문서의 `uploadedByEmail`을 교차 조회하는데 이 경우엔 문서가 없어,
  일반 사용자의 정리 시도는 거부되고 고아 파일이 남을 수 있음(이전과 같은 상태, 악화는 아님).
  해결하려면 Storage 메타데이터에 업로더를 기록하고 규칙을 바꾸는 별도 작업 필요.
- **오프라인에서의 할 일/메모 변경은 몇 초 뒤에 되돌아갈 수 있음.** Firestore 트랜잭션이 SDK 내부
  재시도를 거친 뒤에 실패하기 때문 — 실패 시 스낵바는 뜸(실패까지 걸리는 시간은 측정 안 함).
- **느린 네트워크에서 할 일 추가 시 Enter를 연달아 누르면 중복 추가될 수 있음.** 저장이 끝날 때까지
  입력창을 비우지 않기 때문(실패 시 입력을 보존하려는 동작과 맞물림).
- **Kotlin Gradle Plugin 경고.** `file_saver`, `firebase_auth`, `firebase_core`, `firebase_storage`가
  구식 Kotlin 적용 방식이라 빌드 시 경고가 뜸. 지금은 빌드되지만 이후 Flutter 버전에서는 빌드가
  실패할 수 있어, 그때 해당 패키지 업그레이드(사전 승인 필요)가 필요.
